# 简历一键填表 MVP

一个不依赖服务器或大模型的 Chrome Manifest V3 扩展。它可以在浏览器本地解析 PDF、DOCX、TXT 简历，把识别结果写入本地资料库，并在你点击按钮后填写当前招聘页面中的常见字段和简历附件。

## 安装

1. 打开 Chrome，在地址栏输入 `chrome://extensions/`。
2. 打开右上角的“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择整个 `resume-autofill-mvp` 文件夹。
5. 将“简历一键填表 MVP”固定到浏览器工具栏。

## 使用

1. 点击插件图标，再点击“编辑我的资料”。
2. 拖入 PDF、DOCX 或 TXT 简历进行本地解析；检查识别结果并补全没有识别的信息。
3. 填写至少姓名、手机和邮箱，点击“保存资料”。
4. 打开招聘申请页面并刷新一次。
5. 点击插件图标，然后点击“① 先上传并解析简历”。
6. 阶段结果确认网站已经接收并完成解析后，点击“② 补充填写当前页面”。
7. 绿色边框表示已填写；黄色虚线表示未识别或无法填写。
8. 人工检查文字和附件后，在网页上自行提交。

可以先在本目录的 `test-form.html` 上测试。Chrome 默认不允许扩展访问 `file://` 页面；如需测试本地文件，请在扩展详情中打开“允许访问文件网址”，或者用本地 HTTP 服务打开测试页。

## 当前覆盖

- 姓名、英文名、姓、性别、生日
- 手机、邮箱、微信、城市、地址、邮编
- 身高、体重、生源地、现居地、户籍、民族、政治面貌、婚姻状况
- 多名家庭成员：姓名、关系、电话、工作单位、职业
- 目标职位、期望城市、期望薪资、到岗日期
- 多段教育：学校、学院、专业、学历、学位、学习形式、起止时间、GPA、专业排名
- 多段实习/工作：类型、公司、部门、职位、起止时间和工作内容
- 多段项目、证书和语言情况
- 计算机等级、熟练程度和技能
- LinkedIn、GitHub、作品集、个人介绍
- 部分明确的是/否资格问题
- 普通 input、textarea、select、radio、checkbox 和 contenteditable
- 通过控件语义和交互行为识别自定义下拉框，可选择学历、性别、是/否等选项，不绑定网站或组件库 class
- 单日期以及由年/月拆分的起止时间；支持顶部显示“2026年8月”的月历，以及“年份列表 → 12 个月 → 日期”的分层面板
- 民族、学习形式、英语等级等可搜索或固定选项的自定义选择器
- 籍贯、生源地、户籍及城市等省/市/区级联选择器；资料中的“籍贯”与“户籍所在地”分开保存
- 通过教育、工作、项目、证书、语言等区块标题消除“开始时间”“职责”等重复字段的歧义
- 手机号前的 `+86` 等国家区号辅助下拉框会跳过，不会消耗手机号资料
- 标签明确为“简历 / Resume / CV”的文件上传框

## 匹配逻辑与结果统计

插件先收集字段的 `label`、`name`、`id`、有效 placeholder、ARIA 信息和附近的语义标题，再结合教育/工作/项目等区块上下文映射到本地资料字段。`nope`、`new_password`、`请输入`、`请选择`、报错文字等无意义内容会被过滤。自定义控件按 `combobox/listbox/radio` 语义、可见候选项和点击行为识别，不依赖域名或某个网站的随机 class。

- `已填写`：识别出字段、本地有值且成功写入。
- `跳过已有内容`：页面已有值，且没有勾选覆盖。
- `未识别字段`：无法从字段标签和属性判断含义。
- `资料为空`：识别成功，但本地资料没有对应值。
- `控件不兼容`：识别成功且有值，但网站的自定义控件不接受通用写入。

更新代码后，需要在 `chrome://extensions/` 点击扩展的“重新加载”，并刷新招聘页面，否则页面仍运行旧版本脚本。

0.4.4 为外观普通的学校、学院、专业、公司、职位、部门、项目和证书输入框增加自动完成确认：写入资料后短暂等待候选项，仅在候选文字与资料值精确一致时点击并确认；没有候选项时仍按普通文本保留。

0.4.5 将上述字段正式作为“必须选择候选”的自动完成控件：输入前监听动态 DOM，支持没有 role、li 或特定 class 的 React/Vue `div/span` 弹层；只有精确候选被点击且弹层关闭或出现选中状态才算成功。未出现精确候选时会报告“候选项未确认”，不再把仅写入文字统计为成功。

0.4.6 为所有需要点击交互的自定义下拉、地点级联、日期面板和自动完成控件统一建立“动态交互会话”：点击前记录可见 DOM 并启动监听，只在本次新增或变为可见的弹层中选择候选；选择后必须回读字段值并等待弹层隐藏或移除，才能继续下一个字段。弹层未自动关闭时依次尝试“确定/完成”、点击外部和 Escape；仍未关闭则停止本轮填写，避免残留弹层污染后续字段。

0.4.7 将自动完成结果按“候选对象”选择：例如输入“天津工业大学”后，可匹配包含该校名及城市、院校类型等附加文字的候选行；优先点击候选行的语义可点击容器，无语义时点击承载候选内容的整行，以兼容 React/Vue 事件委托。只有字段回读为目标值且候选弹层消失才算完成。

0.4.8 适配 `sd-Dropdown`/`sd-Select` 一类动态菜单：匹配 `option-label` 的文字后向上定位并点击 `Select-pointer` 候选行，排除菜单分组标题；关闭检测排除包含原输入框的静态 picker/select 外壳，只跟踪点击后独立出现的浮层根节点，避免字段已写入却误报“日期弹层仍未关闭”。

0.4.9 为候选点击增加结果验证和回退：优先点击 `Select-pointer` 整行，检查字段显示值、选中状态、候选可见性或弹层 DOM 是否变化；若完全没有变化，再点击行内 `option-label`。两次点击均无响应时明确报告候选点击失败，不会把仅写入搜索文字当作选择成功。

0.5.0 候选搜索会直接遍历本次浮层根节点内的全部后代，支持网站复用既有弹层 DOM、仅切换显示状态的性别等菜单；`sd-Select` 候选点击依次尝试 `Select-pointer` 整行、菜单内容层和 `option-label`，每次等待页面状态变化。日期关闭阶段额外尝试再次点击触发器收起面板。

0.5.1 根据实际 `sd-Select` 菜单结构，将没有 `Select-pointer` 类的 `Select-common-item` 也识别为正式候选行。从 `option-label` 匹配文字后只向上定位至该候选行，排除同名的 `Menu-header` 省份分组标题；城市和性别菜单均使用此规则。

0.5.2 对选择后保持展开的城市菜单，改为点击页面中真实存在的表单/应用根节点并向 `document` 派发完整鼠标事件来触发组件的 outside-click 关闭逻辑，不再使用临时透明节点；关闭等待延长，并在失败信息中列出仍可见的浮层根节点，方便继续精确适配。

0.5.3 收紧候选点击成功条件：普通 DOM 变化不再算选择成功。依次模拟点击候选行、内容层和文字层后，必须满足字段回读为目标值、候选出现选中状态或候选消失之一；否则继续下一种点击目标并最终报告明确失败。

0.6.0 增加浏览器级点击回退：普通 DOM 合成点击全部失败后，将候选中心点的视口 CSS 坐标发送给后台，后台临时使用 `chrome.debugger` 和 CDP `Input.dispatchMouseEvent` 派发移动、按下、释放事件，随后立即断开调试连接。此功能需要固定 `debugger` 权限，重新加载扩展时 Chrome 会显示调试权限警告。

0.6.1 诊断运行模式不再因为单个动态弹层无法关闭而终止整轮填写。该字段仍记为不兼容并记录残留弹层警告，但继续处理后续字段，以观察通用逻辑能覆盖到什么程度；测试完成后必须人工核对，不应自动提交。

0.6.2 修复日期弹层嵌套在触发控件内部时被过滤的问题，并为 `sd-basic` 年月日组件增加快速专用路径：读取年份标题，通过左右箭头导航到目标年，点击月份整格，等待日期面板后点击目标日；每一步普通点击无效时才调用浏览器级点击回退。

0.6.3 增加 Phoenix 年月选择器适配：识别 `common-unmodeled-layer` / `phoenix-date-picker` 浮层，读取月面板年份，通过 `month-panel-prev-year-btn` / `next-year-btn` 切换目标年，再点击对应 `month-panel-month` 网格并回读年月。

0.6.4 日期打开依次尝试只读输入框、picker 标签、日历图标和控件外壳，并以实际日期弹层出现为成功；普通点击无效时才使用浏览器级点击。起止时间容器按前后两半绑定开始/结束资料，单个完整年月控件不再误判成仅年份下拉。

0.6.5 发现起止时间控件在选择开始值后会重渲染并清空已选 input 的 placeholder，证明不能在填写过程中反复依赖当前展示属性推断逻辑位置。

0.6.6 改为通用结构识别日期范围：在同一语义容器中寻找偶数个日期型控件，并结合中间分隔符、至今/当前语义或 range 语义确定范围；按控件前后两半绑定开始/结束，再按两侧对应位置推断年/月/日。组件 class 只用于交互，不再决定字段含义。
0.6.7 增加“可搜索列表 + 单选状态 + 明确确认”的通用选择协议：先检查当前已渲染的候选行，虚拟列表中没有目标时再写入面板自身的搜索框；点击候选后必须观察到选中状态或已选摘要，再点击确定并等待整个面板消失。`resize-triggers` 一类尺寸监听节点会被排除，不会被当成选项或触发器。
0.6.8 搜索确认式选择器改为统一先写面板自身的搜索框，再从虚拟列表重新渲染出的候选中精确匹配、勾选并确认。完整 Phoenix 日期面板与仅年月面板分流处理：完整日期按年份箭头、月份箭头、当月日期格三阶段执行，并排除上月/下月补位日期。
0.6.9 将拆分式日期范围作为一个原子字段处理：四格结构固定为开始年、开始月、结束年、结束月，六格结构固定为开始年月日和结束年月日。每选择一格后重新从当前 DOM 获取整组控件，避免 React 重渲染让队列中的结束控件失效；只有整组所有格均非空才统计为填写成功。
0.6.10 修复单选图标为 SVG 时调用不存在的 `click()` 导致整轮填写中断的问题。统一点击器现在支持 HTMLElement 与 SVGElement：HTML 使用原生 click，SVG 使用冒泡 MouseEvent；无效或已脱离 DOM 的对象只返回失败，不再抛出未处理异常。
0.6.11 通用动态控件点击不再调用候选对象的 `.click()` 方法，HTML、SVG 与自定义元素全部统一派发完整的 pointer/mouse/click 事件序列，从底层消除 `option.click is not a function`。
0.6.12 日期范围若处于半填写状态，会按资料重新校正整组，不再因为单格非空而跳过错误月份。页面重渲染后按同类范围的页面顺序重新定位新 DOM；最终必须精确回读开始和结束的每个年/月/日都等于资料值，而不仅是检查所有格非空。
0.6.13 日期范围改为多轮补齐：某一格选择失败时不再立即退出，仍继续尝试后面的结束年/月；每轮完成后重新回读整组，只重试与资料不一致的格子。兼容选择年份后组件自动把月份设为 1 的行为，目标四格仍须精确达到资料值才算完成。
0.6.14 搜索确认式民族/地区选择器若存在 `RadioUnchecked/RadioChecked` 图标，只认候选行当前 DOM 中的 `RadioChecked` 为选中成功。依次点击单选圆圈、圆圈容器、候选整行和文字，并在每次重渲染后重新定位候选；确认真实勾选后才点击“确定”。
0.6.15 将 `area-selector-container`、`area-item-container` 和 `area-text-label` 纳入搜索确认式选择协议。地区资料为多级路径时直接取最后一级作为目标，并去除市/区/县等后缀作为搜索关键词，例如“湖北省孝感市”搜索“孝感”、精确勾选“孝感市”，再点击确定。

0.6.19 完整日期不再走普通精确文本候选捷径，也不再用包含整个日历网格的触发器文字判断成功。必须按当前标题移动到目标年和月、点击当月日期，并从原字段、专用显示节点或日历顶部日期输入框精确回读完整年月日后才会关闭弹层。
0.6.20 自定义单选按钮组改为动态双阶段扫描：除原生 radio 外，结构化发现 Phoenix 等由 `div` 组成的性别、婚姻按钮组，读取当前 checked 状态并在点击后复核。诊断结果新增 `choiceGroups`，列出组标题、选项、当前勾选项与字段匹配结果；未识别标题、资料为空、无目标选项及点击失败不再静默跳过。

0.6.24 弹窗流程拆成两个独立按钮：“先上传并解析简历”只处理本地附件、文件框、事件触发和网站解析验证，并逐阶段显示结果；“补充填写当前页面”不再夹带上传，专门在解析后的表单中新增经历区块并补填资料。上传失败时会明确区分未保存附件、未找到文件框、文件已写入但网站未响应等情况。
0.6.25 页面同时存在“快速解析简历”和“简历附件”时，不再按 DOM 顺序尝试：先按上传组件附近语义分类，优先命中包含“快速解析/帮你解析/简历解析”的入口，其次才是普通简历附件。独立上传结果会显示实际命中的入口类型。

## 安全边界

- 不会自动点击提交。
- 默认不覆盖页面已有内容。
- 不填写密码、验证码和普通隐藏字段；只会尝试写入明确标记为“简历 / Resume / CV”的文件框。
- 资料只保存在 `chrome.storage.local`；导出 JSON 后请自行妥善保管。
- 证件号码属于敏感个人资料；插件只在本机扩展存储中保存并按你的点击操作写入当前招聘页面，不会自动提交。
- 本版本不调用任何模型 API。
- PDF.js 和 JSZip 也随扩展本地加载，不会把简历发送到第三方解析服务。

## 已知限制

- 通用版会监听并串行处理带清晰语义或可观察交互行为的自定义下拉、级联地点和日期面板；Canvas 控件、封闭 Shadow DOM、跨域 iframe、依赖真实鼠标轨迹的控件及滚轮式虚拟日期面板仍可能需要人工选择。
- 插件会按本地资料条数尝试补齐教育、实习/工作和项目区块；只有页面按钮具有清晰的章节和“添加/新增”语义、且点击后能观察到新表单时才继续。结构完全不透明的新增按钮会停止并报告。
- 插件会尝试把已保存简历放入明确的简历文件框。跨域 iframe、隐藏封装控件或网站主动拦截时，仍需手动选择附件。
- 扫描版 PDF 没有文字层，当前版本无法 OCR；可先把它转为带文字层的 PDF 或 DOCX。
- 规则解析器已支持“学校＋专业＋GPA/学位＋日期”“公司＋职位＋日期”以及“项目标题＋会议/状态＋日期”等常见横排简历格式，并会按教育、工作/实习和项目章节保存多段记录。非常规排版仍需要人工校正。
- 跨域 iframe 内的表单暂不扫描。
- 重复经历按页面中的字段容器和资料顺序对应；结构完全扁平、没有区块标题的页面可能仍需人工核对。
- 教育经历中的“学历”“学位”“是否最高学历”分别保存；顶层最高学历取明确标记为“是”的教育经历。
